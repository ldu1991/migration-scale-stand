# Час міграції схеми під транзакційним advisory-локом

Стенд для статті про залежність часу міграції схеми PostgreSQL від кількості сесій і мережевої затримки. Клієнти йдуть через Toxiproxy трьома шляхами: прямо в PostgreSQL, через PgBouncer у режимі session і через PgBouncer у режимі transaction.

Міграція створює реєстр `schema_migrations`, вісім прикладних таблиць, дві функції й шість тригерів. Це той самий скрипт, що в попередньому дослідженні, лише таблицю реєстру перейменовано.

У режимі transaction розмір пулу дорівнює 4. У режимі session пул дорівнює 64, тобто не менший за найбільше N, щоб черга пулера не змішувалась із часом лока. Затримку 0, 5 або 20 мс додає токсикант Toxiproxy у напрямку від сервера до клієнта. Нуль означає проксі без токсиканта.

Кожна сесія є окремим процесом. З'єднання відкривається до спільного бар'єра, а відлік часу серії починається в момент його відпускання і закінчується, коли завершується остання сесія. Сесія, яка не завершилась за 60 с після бар'єра, вважається завислою. Перед кожним запуском схема public створюється заново. Порядок запусків перемішано з зерном 20261015.

Коректний запуск: усі N сесій завершились без помилки, схему застосовано один раз, решта N − 1 сесій її пропустили, у реєстрі один запис `schema`, у базі вісім прикладних таблиць, дві функції й шість тригерів.

Основна серія тримає транзакційний лок на всіх трьох шляхах, для N = 2, 4, 8, 16, 32, 64 і затримок 0, 5, 20 мс, по 30 повторів. Контроль без лока йде лише в режимі transaction на тих самих N і затримках. Окремо є контрольна клітинка попереднього дослідження: пряме з'єднання, без лока, N = 8, затримка 0. Разом 2190 запусків.

## Запуск

Потрібен запущений Docker Desktop з рушієм WSL2.

Перевірка обчислень без Docker:

```powershell
node src/self-check.js
```

Пробний прогін:

```powershell
.\scripts\smoke.ps1
```

Основна серія. Якщо процес перерветься, той самий скрипт продовжить із уже записаних запусків:

```powershell
.\scripts\main.ps1
```

Окремий зріз:

```powershell
docker compose run --rm runner node src/run.js --reps 30 --paths transaction --ns 8 --latencies 0
```

Результати лежать у `results/runs.jsonl`, `results/runs-summary.json` і `results/runs-meta.json`. Пробний прогін пише `results/smoke.jsonl`. Підсумок рахує частки з 95% інтервалом Вілсона, медіану й 95-й процентиль часу серії, оцінки залежності T(N) = a + bN методом найменших квадратів і 95% bootstrap-інтервал нахилу на 10 000 переселекціях.

Пароль у стенді не перевіряється. PostgreSQL усередині Docker-мережі приймає з'єднання без пароля. PgBouncer стоїть у режимі auth_type=any і завжди виходить на сервер користувачем postgres. Це лише лабораторна конфігурація.
