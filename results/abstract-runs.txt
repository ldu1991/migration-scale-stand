PARA [Surname N.] Scalability and correctness of PostgreSQL schema migration under a transaction-level advisory lock as the number of concurrent sessions and network latency grow. The paper examines migrations in horizontally scaled Node.js applications, where N replicas started simultaneously try to apply the same migration through the PgBouncer pooler. A previous study showed that pg_advisory_xact_lock preserves mutual exclusion in the pooler's transaction mode, but how the cost of serialization depends on N and latency remained unknown. The aim is to test the hypothesis that under this lock the migration stays correct for N up to 64 and latency up to 20 ms, while the series time grows linearly with N and skipping an applied migration is much faster than applying it. The experiments ran on PostgreSQL 18 and PgBouncer [version] in Docker, with latency injected by Toxiproxy and at least 30 repetitions per combination of path, N and latency. A run was correct if the schema was applied once, N − 1 sessions skipped it and no errors occurred. Time dependence on N was estimated by least squares with 95% bootstrap intervals.
